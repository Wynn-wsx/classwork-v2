## 一、版本目标与角色体系

从"老师用的积分管理工具"升级为"全班共用的班级平台"。五级角色：

| 层级 | 显示名 | 标识 | 说明 |
|---|---|---|---|
| 最高 | 管理员 | `super_admin` | **新增**，班主任权限的超集，另有专属权限 |
| 1 | 班主任 | `admin` | 班级日常管理最高负责人 |
| 2 | 执行管理 | `executive` | 登记、规则、抽选内容、导出 |
| 3 | 小组记录员 | `group_recorder` | 仅本组登记与查看 |
| 4 | 学生 | `student` | **新增**，本人数据 + 抽选 + 申诉 + 信箱 |
| 临时 | 监督委员 | `student` + 当周指派 | 普通学生临时担任（每周老师指派 2 名）：抽查记录只读、共同受理申诉，任期 1 周 |

- **监督委员不是独立角色等级**，而是学生身上的"当周临时授权"：通过 `supervisor_assignments`（周 period_key + 学生 + 指派人）生效，RLS/RPC 按"当前登记周是否在指派名单内"实时判断，到期自动失效；V2.0 先做老师手动指派，自动抽签列入后续。

### 模块范围（本期）

积分管理（已完工）｜周/月时间规则与冻结｜积分规则周期上限｜奖惩抽选（两池 + 仓库 + 周/月双触发）｜星光值台账｜周/月汇总快照｜通知信箱｜学生账号与自助注册｜积分异议申诉｜监督委员（临时）｜五级角色与系统配置｜操作审计日志。

**【确定】**暂不整合其他模块（值日、请假、班级活动等）；班级日记「拾光记」继续保持独立、不纳入。

## 三、需求口径（已确定汇总）

### 3.1 时间规则（东八区）

- 业务时区统一 Asia/Shanghai（UTC+8）；库存 `timestamptz`，界面按北京时间展示。
- **周分隔点**：规则生成（默认每周一 00:00，【待验证】时刻你定）+ 可手动增删。作用：①隔开登记周；②**默认就是规则更新点**（重置各项目周期上限计数）；③到点自动生成**周汇总快照**并发通知。**周分隔点不冻结登记**。
- **月分隔点**：规则生成（默认每月 1 日 00:00，【待验证】）+ 可手动增删。作用：①隔开登记月；②到点执行月度结算；③**过去的登记月自动冻结**，禁止新增/修改/删除积分记录（C4 管理员纠错除外）；④同时重置规则上限。
- 分隔点**预生成未来 12 个月**实例，管理员可改规则（B1）、班主任可手动增删具体实例（B2，如节假日顺延）。
- **登记时间限制器**：①登记日期晚于系统当前时间（未来）→ 禁止；②落在已冻结登记月 → 禁止。
- **2 秒冻结**：每条积分记录写入后冻结 2 秒，冻结期间**仅该条记录**不可修改/删除（不影响该学生其他数据）。

### 3.2 积分规则周期上限

- 规则可配置"每周期次数上限"或"每周期分值上限"，不启用则留空。
- 周期边界 = 最近一个规则更新点（周分隔点 / 自定义更新点 / 月分隔点）。
- 计数实时统计该周期内该规则的有效记录，超限拒绝登记；更新点只重置计数，不清积分。

### 3.3 奖惩抽选（两池独立，周/月双触发）

**奖励次数（进入个人当月次数池，学生自己抽，月末未用自动抽）**
- **周触发（每周分隔点结算）**：本周**小组积分前 3 名**的小组，**组内每人 +1 次**奖励抽选。（PDF 原"周个人前 3"发卡**取消**。）
- **月触发（每月分隔点结算）**：每人奖励次数 = **max( floor(月个人累计加分 ÷ 10) , 若位列月个人前 15 名则 1 否则 0 )**（**max 去重**，不叠加）。例：满 10 分且前 15→1 次；满 20 分→2 次；没满 10 分但前 15→1 次；都不满足→0。
- 周、月获得的次数都在**当前月内有效**，月末未用自动抽、次月清零。

**惩罚次数/触发**
- **周触发（小组级）**：本周**小组积分后 3 名**的小组，**每组派代表抽 1 次**惩罚大转盘，抽出的 **1 条由全组共同执行**；结果全组可见（系统为每个后 3 名小组生成 1 条小组级抽选记录，关联全组成员，发送通知）。【待验证】由组长/组员到点点击抽、超时系统自动抽，还是结算时直接自动抽。
- **月触发（个人级）**：①个人当月累计扣分每满 5 分得 1 次（floor，-12→2 次）；②**第二类**（月个人净积分全班倒数十名）每人额外 +1 次。【待验证】①与②叠加。
- **第二类并列**：【待验证】第 10 名同分并列都算（可能 >10 人）；不足 10 人按实际人数。
  - **第二类奖励口径（二次确认最终版）**：第二类学生**未使用的奖励次数月末照常自动抽选**，所有抽奖结果（月中已抽 + 月末自动抽）**一律保留、不作废、不追回**；**仅在该月月度汇总账面将其奖励抽选资格标注为"作废"**（`reward_forfeit`，资格层面查账标注，不影响任何已抽到的结果）。

**通用**
- 次数以月分隔点划界，**上月积分不参与**；积分本身不清零（积分累计是已完工机制）。
- 月分隔点到点：**暂停服务 30 分钟**（全站只读 + 维护提示，显示预计恢复时间）；**未用次数自动抽选**；自动抽选结果通知本人。
- 【待验证】自动抽选时对应池子为空：建议落"本期奖池为空，未抽中"记录、不补抽。
- **抽选操作人**：个人奖励/惩罚由学生本人抽（老师 D6 可代抽）；小组周惩罚由该组代表抽 1 次（全组共担）。
- **奖励池（8 种卡，来自《班级奖励卡使用规则》，概率即权重，可在池子管理中调整）**：

| 卡 | 概率 | 类别 | 有效期 |
|---|---|---|---|
| 指定惩罚卡 | 11% | 功能卡 | 至月分隔点 |
| 免罚卡 | 11% | 功能卡 | 至月分隔点 |
| 免扣分卡 | 11% | 功能卡 | 至月分隔点 |
| 3 星光卡 | 15% | 星光卡 | 抽中即自动入星光台账 |
| 5 星光卡 | 15% | 星光卡 | 抽中即自动入星光台账 |
| 10 星光卡 | 15% | 星光卡 | 抽中即自动入星光台账 |
| 免值日卡 | 11% | 功能卡 | 至月分隔点 |
| 万能卡 | 8% | 功能卡 | 至月分隔点（可兑换任意 1 张卡） |

- **惩罚池（20 条，来自 punishments.txt，默认等概率，可调整）**：绕丹阳广场跑 3 圈、教室全面清扫连续 2 天、连续 3 天请教老师、写 300 字反思、辅导学困生连续一周、检查门窗电器连续 1 周、写改正计划书、朗读励志文章、整理教具连续 1 周、抄写励志名言 20 条、班会自我反省发言、**星光积分扣除 3 颗**、**星光积分扣除 5 颗**、整理劳动工具连续 1 周、换水连续一周、给未来自己的信、道歉信、班级绿植养护 1 周、协助值日、写出一组组员优点等（原文 20 条全部录入，措辞以 `punishments.txt` 为准）。
- **抽选结果仓库**：
  - **功能卡（非星光卡）**：抽中即入仓库，**有效期统一到下一个月分隔点**（抽中当月有效，跨月失效）；月度结算时把未使用的功能卡自动置为"已过期"。仓库状态：未使用 / 已使用 / 已过期 / 已作废。
  - **卡片使用（回收）登记权限下放给执行小组（`executive` 及以上）**：实际用卡仍走纸卡 + 登记员流程，由执行小组在系统里标记"已使用/已回收"（学生本人不能标记）；免扣分卡等关联具体扣分事件时可附记录编号。
  - **星光卡不入仓库**：抽中即自动转星光值（3/5/10），抽选记录显示"已入账 +X 星光"。
  - **惩罚池的"扣星光 3/5 颗"**：抽中即自动从星光台账扣除，写流水。
  - 有效期规则类型保留通用能力：至月分隔点（本系统卡片默认）/ 抽中后 N 天 / 固定到期日 / 永久。
  - 【待验证】万能卡兑换为具体卡种后，新卡的有效期：建议按兑换操作时点到下一个月分隔点计算（执行小组登记"万能卡已使用→换为 XX 卡"时新卡入库）。

### 3.4 周/月汇总（两层独立、互不影响）

- **周汇总**：周分隔点到点自动存快照（每人周积分与并列名次、小组汇总），发通知；周与周独立。
- **月汇总**：月分隔点结算时存快照（全班排名、第二类名单、每人奖励/惩罚的应得/已抽/自动抽/资格作废、自动抽选数量）。
- 月度结算只"新增"快照与抽选记录、清零次数，**不改不删任何积分流水**，所以历史任意周的汇总按区间复现结果不变。

### 3.5 通知信箱

- 触发点：周汇总生成、月结算维护开始、月结算完成、每次抽选结果（手动/自动）、申诉状态变化、系统广播。
- 接收对象：个人（抽选结果、申诉结果、个人汇总）→ 本人；广播（维护、全班通知）→ 全体；管理通知（申诉待处理、注册待审核）→ 管理员/班主任。
- 顶部铃铛 + 未读红点；登录拉取、每 60 秒轮询未读数（不引 Realtime）；通知信箱页：未读加粗、点开即已读、一键全部已读、按类别筛选、点击跳转。

### 3.6 学生账号（批量 + 邀请码，两者结合）

- **批量建号**：学生管理页一键为无账号学生建号；用户名=学号；初始密码统一 **123456**（B7 可由管理员改）；**首次登录强制改密**。
- **邀请码自助注册**：登录页注册入口，填班级邀请码（A7 管理，可重置/停用）+ 姓名 + 学号；
  - 与名单匹配后：按 B5 配置"直接激活"或"始终需审核"（默认建议始终需审核，防冒名）；
  - 与名单不匹配：进入待审核，由 A4 审核确认/驳回（防陌生人）。
- 账号状态：正常 / 待审核 / 已停用；待审核不能进入应用，停用账号登录被拒。

### 3.7 学生信息可见范围（管理员可随时切换）

存系统配置，RLS 层强制，切换即时生效：
- `self_rank`（默认）：明细只能看自己；排行榜公开（仅姓名/小组/总分/名次，不含加扣分原因）。
- `all_open`：全班积分明细互相可见。
- `self_only`：除自己外，排行榜也不可见。

### 3.8 积分异议申诉

- 学生选一条记录（或不指定）提交理由 → 通知班主任/管理员；
- 老师处理：通过/驳回 + 处理意见 → 通知学生；
- 申诉不自动改分，是否调整由老师另行操作并留痕；
- 已冻结月份记录申诉：**默认关闭**（B6 开关，开启后作为冻结月唯一纠错入口）。

### 3.9 星光值台账（独立体系，只做台账，不做兑换）

- **【确定】只做台账**：星光值与班级加扣分积分是**两套独立体系、不可互转**（《星光兑换规则》明确）。本系统只做星光账户与流水，**不做兑换/库存/2:1 实物/二四六兑换窗口**（兑换继续走人工与现有「星光积分抽奖.exe」）。
- **获取（系统内自动入账）**：
  1. 奖励抽中 3/5/10 星光卡 → 抽中即自动 +3/+5/+10 到星光台账（卡片不入库）；
  2. 惩罚抽中"扣星光 3/5 颗" → 自动 -3/-5 并写流水；
  3. 老师可人工登记调整（纠错、补录），强制留痕。
- **持有与有效期**：星光卡抽中即入账，无卡片留存形态；星光值**本学期有效、学期末清零**。
- **学期清零（手动）**：**不设学期分隔点**；学期结束时由有权限的人在设置页手动点「学期清零」，清零前自动留存一份学期星光快照（每人余额、总增减）。执行角色【待验证】，建议 `super_admin`（与数据类危险操作同级）。
- **公示**：星光台账单独页面公示（PDF 要求与积分分开公示）。【待验证】可见范围：默认全班可查每人星光值与流水（公开台账）；也可改为仅本人+老师。
- 学生端「我的仓库」之外另设「我的星光」：余额、本人流水、本学期状态。

### 4.3 新增 RPC（security definer，服务端强制权限/时间/冻结/上限）

**积分记录（含时间限制、2 秒冻结、上限、留痕）**
- `add_record(...)`、`update_record(...)`、`delete_record(...)`：校验角色与本组（记录员）、未来时间、冻结月、2 秒冻结、规则上限；写 `frozen_until=now()+2s`、`period_key`；关键动作写 `audit_logs`。
- `admin_fix_frozen_record(...)`：C4 管理员冻结月纠错（强制留痕）。

**周期与配置**
- `get_period_state()`：当前登记周/月、是否冻结、维护状态、各配置。
- `admin_save_separator_rules(...)`（B1 管理员）、`admin_add_boundary / admin_delete_boundary`（B2 班主任+管理员）、`admin_set_config(jsonb)`（按 B3–B8 权限逐项校验角色）。
- `admin_toggle_maintenance(...)`（B3 应急解除）。

**抽选**
- `draw_lottery(p_student_id, p_pool_type, p_group_id)`：学生本人或有代抽权角色；校验剩余次数、维护期、权限、学生状态；加权随机抽条目，写仓库并计算有效期，发通知。小组周惩罚（`p_group_id`）由代表抽、全组共担，结果写小组级记录。
- `list_lottery_chances(p_period_key)`：每人本月应得/已抽/剩余奖励、惩罚次数（读 `lottery_chances`，区分来源 weekly_group/monthly_points/monthly_top15/penalty_points/second_class/group_penalty）。
- `admin_save_lottery_item / toggle_lottery_item / delete_lottery_item`（D5）、`admin_void_draw`（D6 撤销，管理员+班主任）。
- `mark_draw_used(p_draw_id, p_related_record_id, p_note)`：**执行小组（executive 及以上）**标记功能卡已使用/回收；万能卡可指定兑换卡种并生成新卡（有效期按当前月分隔点）；学生无权调用。
- `weekly_snapshot(p_boundary_id)`（事务、幂等）：①写周汇总快照；②按本周小组积分排名——**前 3 组每人 +1 奖励次数**（source=weekly_group，入当月）；③**后 3 组每组生成 1 条小组级惩罚抽选**（代表抽/全组执行，关联全组成员，发通知）；④周星光个人/小组作为荣誉标记写入快照。
- `monthly_settle(p_boundary_id)`（事务、幂等、advisory lock）：①写月结算快照；②个人奖励次数 = max(floor(月加分/10), 月前15则1)，个人惩罚 = floor(月扣分/5) + 第二类+1；③第二类资格层面标 `reward_forfeit`（结果不追回）；④功能卡未使用置 `expired`；⑤未用次数自动抽选；⑥星光卡/扣星光已即时入账，不重复处理。
- `maybe_run_period_jobs()`（cron 每 10 分钟调）、`admin_resettle(p_boundary_id)`（E4 管理员，回滚/重算）。

**监督委员（临时授权）**
- `admin_assign_supervisor(p_period_key, p_student_id[])`（D15，管理员+班主任，每周 2 名）、`admin_revoke_supervisor`、`list_supervisors(p_period_key)`。
- 申诉受理 `handle_appeal` 与记录只读校验内联判断"当前周是否在 `supervisor_assignments` 名单"。

**星光值台账（独立体系，只做台账）**
- `draw_lottery` 内部：抽中星光卡 → 自动写 `starlight_accounts` 与 `starlight_logs`（+3/+5/+10，draw 状态 posted）；抽中扣星光惩罚 → 自动扣减（-3/-5）。
- `starlight_list(p_scope)`：台账与流水查询（公示范围按配置）。
- `starlight_adjust(p_student_id, p_amount, p_note)`：老师人工调整（executive 及以上，留痕）。
- `term_reset_starlight(p_term_name)`（学期手动清零，权限【待验证】默认 `super_admin`）：先写 `starlight_term_snapshots` 快照，再将余额清零并为每人写 term_reset 流水。

**账号（五级角色）**
- `admin_create_user` 扩展：支持 `super_admin`（仅管理员可建，A8）、`student`（批量建号走专用函数）。
- `admin_batch_create_students(p_password)`（A3）：为无账号学生批量建号，初始默认 123456，置 `must_change_password`。
- `student_register(p_code, p_no, p_name, p_password)`（公开可调，无需登录）：校验邀请码与开关，匹配名单，按 register_policy 激活或置 pending。
- `admin_review_student(p_id, p_approve)`（A4）、`admin_set_user_status`（A5）、`admin_change_user_role`（A6）、`admin_reset_password`（A2，管理员）。
- `change_my_password(p_old,p_new)`：所有用户改自己密码，清除强制改密标记。

**通知 / 申诉 / 审计**
- `notify(p_recipient_or_audience, ...)`（内部函数，供各 RPC/cron 调用）、`mark_notification_read`、`mark_all_notifications_read`。
- `admin_publish_broadcast(...)`（D8）、`admin_delete_notification(...)`（D9）。
- `submit_appeal(...)`、`list_appeals(...)`、`handle_appeal(...)`（D7）。
- `admin_restore_backup(jsonb)`（C2，替代现有前端直接重灌）、`admin_purge_*`（C3/C5）。

### 4.4 RLS 要点

- 新表默认 authenticated 可读范围内数据；写一律走 RPC、撤销直接写。
- `students`：`super_admin/admin/executive` 全部；记录员本组；学生按 `student_visibility` 配置决定是否可读全班（排名公开数据走 `student_rankings` RPC，仅返回姓名/小组/总分/名次）。
- `records`：老师全部/本组；学生仅本人（`student_id = 绑定我的 student_id`）；`all_open` 时学生可读全部（策略内引用 `app_config` 配置，配置变更即时生效）。
- `lottery_draws / lottery_chances / appeals`：学生仅本人；小组级 draw 组内成员可读；老师按层级；记录员本组；当周监督委员可读 appeals 与全部 records（只读）。
- `supervisor_assignments`：登录可读（每周监督委员名单公示）；写仅指派 RPC。
- `starlight_accounts / starlight_logs`：星光台账按公示配置（默认全班登录可读，实现"分开公示"；若改为仅本人则按绑定学生过滤）；写一律走 RPC（抽卡/扣罚自动、人工调整留痕）。
- `starlight_term_snapshots`：登录可读；写仅学期清零 RPC。
- `notifications`：只能读自己 `recipient_id` 的行；已读只改自己的。
- `app_config / boundaries / weekly_summaries / settlements / lottery_items`：登录可读；写仅对应 RPC。
- `audit_logs`：仅 `super_admin/admin` 可读（E1/E2）。
- 所有 RPC 内部用 `auth_role()` 判定，`super_admin` 直接放行；专属权限函数中精确匹配角色。

### 4.5 pg_cron 定时作业（V2.0.17 起已取消）

> **现状（2026-10-31）**：pg_cron 作业已全部删除，周汇总/月结算改为管理员在页面上手动触发。本节保留为设计记录，`maybe_run_period_jobs()` 仍可用于手动批量处理。

- 事实：pg_cron 在 Supabase 含免费版默认启用（官方文档 https://supabase.com/docs/guides/cron ）；作业以数据库内部权限运行，能调用 security definer 函数。
- **一个轮询作业**：每 10 分钟执行 `maybe_run_period_jobs()`：
  - 发现到期未处理的周分隔点 → 生成周快照 + 发通知；
  - 发现到期未处理的月分隔点 → 置 `maintenance_until=boundary_at+30min` → 跑 `monthly_settle`（定第二类、抽选、清零、写汇总、发通知）；
  - advisory lock 防重入，结果写 `settlements`；`maintenance_until` 到点前端自动恢复。
- cron 表达式按 UTC 或显式 `'Asia/Shanghai'` 时区参数。
- 【待验证】10 分钟轮询精度：自动抽选实际触发最多晚于分隔点 10 分钟；若要严格准点，改为调整分隔点时注册精确一次性作业。
- 交付 SQL 与控制台执行步骤（我无控制台权限，需你在 SQL Editor 执行，执行前先备份）。

## 八、风险与限制

- 我无 Supabase 控制台权限：M2/M3 的 SQL 需你在 SQL Editor 执行；我提供完整脚本、步骤与回滚方案。
- 收回 `records` 直接写权限是破坏性架构变更：迁移 SQL 必须同时替换前端调用，测试项目跑通前不动线上。
- 邀请码注册需在 Supabase 开放有限注册：通过专用 RPC 实现（不开放匿名注册），注册即与学生名单匹配，陌生人进待审核。
- 无实时订阅：通知未读数用 60 秒轮询；结算结果以数据库为准。
- 单文件规模将显著增大（预计 3500–4500 行），仍保持无构建；如后续继续膨胀，再评估是否拆模块（届时为独立议题）。
- 免费版容量：单班几十人、流水与通知量很小，pg_cron 与认证额度均充足（已查证官方文档，上线前建议在控制台实测）。
