# 周期定义改造方案（V2.0.17 草案）

> 目标：把「周/月分隔点（时间点）」改为「周期区间（起止日期）」，并把「规则分隔点」并入周周期作为「规则计分周数」。

---

## 一、现状与问题

当前 `public.boundaries` 存的是**分隔点（时刻）**：

| 字段 | 含义 |
|---|---|
| `type` | `week` / `month` / `rule_update` |
| `boundary_at` | 分隔发生时刻（东八区，周一 00:00 / 每月 1 日 00:00） |
| `period_key` | 分隔点**关闭的那一周/月**：周 `IYYY-IW`，月 `YYYY-MM` |
| `settled` | 是否已跑过汇总/结算 |

痛点：
1. 用户心智是「这一周从 9/1 到 9/7」「这个月从 9/5 到 10/4」，而不是「9/8 00:00 是个分隔点」；
2. 边界是"点"，一旦想临时改周期（如国庆周按 8 天算），只能靠"立即分隔 + 手动补点"，容易错位；
3. 规则分隔点（`rule_update`）是独立的一类点，语义与"这一周按几轮规则算"重复且不直观；
4. 月只能整月切换，无法"先定开始、后定结束"。

---

## 二、目标模型（一句话）

**周期 = 明确的起止日期区间**；周可选「按几个规则计分周算」；月的结束日次日自动成为下月起始日。

### 2.1 数据结构（改造 `public.boundaries`，不新建表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 主键 |
| `type` | text | `week` / `month`（**废弃 `rule_update`**，历史行保留并标 `deprecated`） |
| `start_date` | date | 区间首日（含），北京自然日 |
| `end_date` | date | 区间末日（含）；**月的进行中周期可为 NULL** |
| `rule_weeks` | int | 规则计分周数，默认 1（≥1，≤4）；仅 week 有意义，month 恒为 1 |
| `period_key` | text | 业务键 = `start_date` 的 `YYYY-MM-DD`（唯一） |
| `boundary_at` | timestamptz | 派生：`end_date + 1 天 00:00`（东八区），`end_date` 为空则为 NULL；保留以兼容 `settled`/cron |
| `label` | text | 展示名（自动生成如「9 月 1 日 ~ 9 月 7 日」） |
| `settled` | bool | 是否已汇总/结算 |
| `is_manual` | bool | 是否人工改过（相对批量生成） |
| `deprecated` | bool | 旧 `rule_update` 行标记 |

唯一约束：`(type, start_date)`；周不得跨月（见 3.3）。

### 2.2 周期键变化（已确认）

- 键 = **起止日期**：`2026-09-01~2026-09-07`（周）、`2026-09-01~2026-09-30`（月）
- 数据库内补零存储（保证字典序 = 时间序）；界面显示为 `2026-9-1 ~ 2026-9-7`
- 唯一的例外：进行中的月（`end_date` 为空）键记为 `2026-09-01~`（开放区间）

### 2.3 规则计分周（替代 `rule_update`，已确认）

- 每个周周期带 `rule_weeks`（默认 1，≥1，≤4）。
- 语义：**该周的规则上限额度 = 单周期上限 × rule_weeks**（次数与分值同倍）。
  - 例：某规则上限 2 次/周，某周 `rule_weeks=2` → 该周可登记 4 次。
- 只影响「积分登记的规则上限」，**不影响**周汇总排名、月汇总、抽选。
- 周期起点仍取当前周的 `start_date 00:00`。

## 三、业务规则与校验

### 3.1 月周期

1. 设置方式：**两段式** —— 先填「开始日期」（此时 `end_date` 为空＝进行中），之后再填「结束日期」把该月关掉。
2. 结束日期 = 下一个月开始日期 − 1 天；设置结束后**自动创建/校正下一月**：
   - 下一月已存在且 `start_date ≠ 结束日+1` → 自动改其 `start_date`；
   - 下一月不存在 → 自动建一条（`end_date` 为空）。
3. 校验：`start_date` 与 `end_date` 都必须**落在某周的 start / end 上**（见 3.3）。
4. 同一时刻**最多一个进行中月**（`end_date IS NULL`）。
5. 月结算触发：`end_date` 次日 00:00 后由 cron 结算（沿用 `settled`）。
6. 冻结判定：`record_date <= 最近一个已结束月的 end_date` → 只读（管理员纠错除外）。

### 3.2 周周期

1. 设置方式：直接填「开始日期 / 结束日期」（可跨 1~2 周，如 9/29~10/5），并可选「规则计分周数」。
2. 周区间必须**首尾相接**：`下一周.start = 本周.end + 1 天`；不允许空洞/重叠。
3. 允许**跨自然月**（用户已确认）：如 9/29~10/5 属于完整一周，只是该周整体落在包含它的月区间内。

### 3.3 周与月的关系（已确认）

用户口径：**周可以跨自然月（如 9/29 ~ 10/5），但设置月的起止日期时必须落在周边界上**——月不会把某一周劈成两半。

由此得到两条校验：

1. 每个月的 `start_date` 必须等于某周的 `start_date`；
2. 每个月的 `end_date` 必须等于某周的 `end_date`。

效果：
- 例：周为 9/22~9/28、9/29~10/5、10/6~10/12……；则 9 月可以设成 `9/1 ~ 9/28`，10 月从 `9/29` 开始到 `10/12` 结束（而非 10/1）。
- 月汇总 = 该月区间内所有完整周之和；跨月周整体归入包含它的那个月。
- 校验失败时提示："该日期不在周边界上，可设为 9/28 或 10/5"。 

### 3.4 完成度与提示

- 周期表若存在空洞（某天不属于任何周/月）→ 设置页红色提示 + `add_record` 拒绝："该日期不在任何周期内，请先在设置里补齐周期"。
- 若 `end_date NULL` 的月之后还有月 → 冲突，拒绝保存。

## 四、接口改造

### 4.1 废弃/替换

| 旧接口 | 处理 |
|---|---|
| `ensure_boundaries()`（按规则自动生成） | **删除批量生成**；新建仅插入「当前周」与「当前月（进行中）」各一条作为起点，之后全部手动维护 |
| `admin_save_separator_rules(week_rule, month_rule, maintenance_minutes)` | 仅保留维护时长；周/月规则字段保留但不再驱动周期 |
| `admin_add_boundary(type, boundary_at, label)` | → `admin_set_period(p_type, p_start date, p_end date, p_rule_weeks int)` |
| `admin_edit_boundary(p_id, p_boundary_at, label)` | → `admin_set_period(...)` 按 id 或 start 更新 |
| `admin_create_immediate_boundary(type)` | → `admin_close_current_period(p_type)`：把当前周期 `end_date` 设为今天，自动开下一周期 |
| `admin_delete_boundary(ies)` / `admin_delete_boundaries` | 保留，但限制：已结算周期仍可删（级联快照）；删除后若出现空洞由校验提示 |
| `admin_regenerate_boundaries()` | 删除（改为手动设置） |

### 4.2 新增

| 接口 | 说明 |
|---|---|
| `admin_set_period(p_type, p_start, p_end, p_rule_weeks)` | 新建/修改一个周期；周可设 `rule_weeks`，月可只给 `start`（进行中） |
| `admin_close_period(p_type)` | 立即结束当前周期（end_date = 今天），并自动开下一周期 |
| `admin_validate_periods()` | 返回空洞 / 重叠 / 月边界不在周边界上 / 多个进行中月 等问题列表 |
| `admin_fill_gap(p_type, p_from, p_to)` | 一键补齐空洞（按周一起 / 自然月模板，仅辅助） |

### 4.3 内部函数改写要点

| 位置 | 改动 |
|---|---|
| `boundary_of(type)` | 改为 `period_of(p_type)`：按"包含今天"的区间取行；无则取最近已结束 |
| `current_week_key()` / `current_month_key()` | 返回 `start_date` 文本；`month_key` 对进行中月有效 |
| `next_month_boundary_at()` | 改为 `current_month_end + 1 天 00:00`（进行中月为空） |
| `check_rule_limit` | 起点 = 本周 `start_date 00:00`；上限乘 `rule_weeks` |
| `weekly_snapshot(boundary_id)` | 用 `start_date/end_date` 取区间；键用 `period_key` |
| `monthly_settle(boundary_id)` | 同上；`end_date` 为空则拒绝 |
| `is_month_frozen(date)` | 用最近已结束月 `end_date` 比较 |
| `add_record` | `period_key` = 所在月区间键；同时拒绝"无周期日期" |
| `list_group_chances` / `draw_group_lottery` / `admin_group_week_board` | 周键改 `start_date`；周区间由行直接给出 |
| `list_summary_periods` / `get_period_summary` | 周/月键改 `start_date`，文案带起止日期 |

## 五、数据迁移（一次性，可回滚）

### 5.1 升级步骤

1. 备份：`boundaries` / `records` / `lottery_chances` / `lottery_draws` / `lottery_group_chances` / `weekly_summaries` / `settlements` / `starlight_logs` 全量导出（脚本化，带 SHA256）。
2. 周区间反推（**周不变，只换表示法**）：
   - `end_date = boundary_at 东八区日期 − 1 天`
   - `start_date = end_date − 6 天`（与上一周衔接则取 `上一周.end + 1`）
   - `period_key = start_date ~ end_date`
3. **历史月区间按周边界重排**（用户要求对齐）：
   - 某自然月的区间 = 「包含该月 1 日的周」的 `start_date` ~ 「包含该月最后一日的周」的 `end_date`
   - 例：2026-09 → 周为 8/31~9/6 … 9/28~10/4 ⇒ 新 9 月区间 = `2026-08-31 ~ 2026-10-04`，10 月从 10/5 开始
   - 相邻月首尾相接、无空洞、无重叠；月不会再劈开任何一周
4. 回填业务键（旧 `YYYY-MM` → 新月区间键）：
   - `records.period_key`：按 `record_date` 落在哪个月区间重算
   - `lottery_chances` / `lottery_draws` / `lottery_group_chances` / `starlight_logs` 的 `period_key` 同法映射
   - `weekly_summaries.period_key` 改为周区间键；`settlements.period_key` 改为月区间键
5. 旧 `rule_update` 行置 `deprecated=true`（不再参与上限计算）；历史月的 `settled` 标记**全部清零**，等待重算。
6. 重算：对受影响的历史月逐月跑 `monthly_settle`（含 2026-08、2026-09、2026-10 进行中除外）；周快照不重算（周区间未变），但周键要跟着改。
7. 迁移后跑 `admin_validate_periods()` 必须 0 问题；再做一次对账（各班总分、9 月净分排名与原值比对）。

### 5.2 影响与风险（必须提前说清）

| 影响 | 说明 |
|---|---|
| 月结算数字会变 | 月区间从「自然月」变成「整周对齐」，月首尾最多相差 6 天，因此月净分排名、奖励/惩罚次数、第二类名单都可能变化 |
| 已抽的奖励/惩罚 | **不追回、不作废**（历史抽选结果保留）；但对应月份的「应得次数」会按新口径重算 |
| 月度冻结范围 | 冻结月改为「最近一个已结束的月区间」，边界随之移动 |
| 历史快照 | `weekly_summaries` 内容不变，只是键换成周区间键；`settlements` 旧行置 `rolled_back` 后重算 |
| 前端文案 | 所有「2026-43」「2026-09」显示改为「9/1 ~ 9/7」「8/31 ~ 10/4」 |

## 六、已确认口径（2026-10-31）

1. **规则计分周**：`上限 × N`（单条规则本周期额度 = `limit_value × rule_weeks`）。
2. **周可跨自然月**，但**月的起止必须落在周边界上**（月不得劈开某周）；失败提示可选的合法日期。
3. **周期键 = 起止日期**：`2026-09-01~2026-09-07`（库内补零，界面显示 `2026-9-1 ~ 2026-9-7`）。
4. **不做批量铺底**：周期全部手动设置；仅新建库/升级时自动插入「当前周 + 当前月（进行中）」作为起点。
5. **历史周期对齐新规则**：月区间按周边界重排，然后重算历史月结算（数字会变，见 5.2）。

### 7.1 需要你知情的一件事

历史月重排后，**已有的 2026-08 / 2026-09 月结算数字会变**（因为月份首尾挪了最多 6 天）。
我的做法是：旧结算行保留并标 `rolled_back`（可查），按新区间重算生成新行；**已抽出的奖励/惩罚结果不追回、不作废**。
如果你希望「历史月份保持老数字、只管以后」，告诉我一声，我就只对新周期生效（迁移步骤 5.1 第 6 步的历史重算跳过）。
